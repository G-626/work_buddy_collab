07 · WorkBuddy usage 08/10

Native skills. Automation. Per-person delivery.

skill.yml manifests

Each skill ships the WorkBuddy-native metadata file — name, description, allowed-tools, config — plus SKILL.md. Uploadable as a folder or a .zip.

allowed-tools: Read, Write, Bash

The agent reads the session folder, writes the artifacts, and runs the engine scripts. A capability contract, not a daemon.

Automation tasks

A daily task checks each student's next-session marker. The day before a session it collects parent and teacher replies and drafts the pre-session brief.

Per-person delivery

Each stakeholder receives only their view, via their own messenger DM — read-only by construction. Replies feed the next session's hypothesis.

No hosted web app, no custom logins. The per-user DM is the per-login document.

08 · Honest limits 09/10

Secure by design — disclosed, not hidden.

  • Local transcription — audio is transcribed on-device (Whisper); the recording never leaves the worker's machine.
  • Remote summarisation, disclosed — WorkBuddy sends content to third-party LLMs (retention up to 14 days, Singapore / PRC transfer). We say “secure by design” — human-in-the-loop review, pseudonymised data, local transcription. We never say “everything stays local”.
  • Observables only — no microexpression-to-emotion claims. The machine reports events; the therapist interprets.
  • Fictional demo data — Marco and Priya are fixtures. No real child's audio or identity anywhere.
